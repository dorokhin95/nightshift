# 1. Общая концепция

Необходимо с нуля разработать полноценную казуальную игру жанра **Match-3 («три в ряд»)**.

Игра должна работать из одной кодовой базы:

- в браузере на ПК;
- в браузере Android;
- в браузере iPhone/iPad;
- как устанавливаемое PWA-приложение;
- как Telegram Mini App;
- непосредственно с GitHub Pages.

Основной адрес клиента:

`https://<username>.github.io/<repository>/`

или, если используется отдельный user-site:

`https://<username>.github.io/`

GitHub Pages используется только для размещения клиентской части игры. GitHub Pages является статическим хостингом HTML/CSS/JavaScript и не должен использоваться как backend.

Для рейтингов, Telegram-авторизации, защищённого сохранения результатов и синхронизации использовать отдельный serverless backend.

# 2. Краткое описание игры

Игрок попадает в яркий неоновый гастробар **«Последний Заказ»**, расположенный в вымышленном районе большого ночного города.

Каждую ночь заведение переживает настоящий хаос: заказы смешиваются, подносы переполняются, продукты оказываются не на своих местах, а персонал едва успевает обслуживать гостей.

Игрок помогает бару справляться с потоком заказов, собирая одинаковые предметы по три и более в ряд.

Основными игровыми фишками являются стилизованные:

- бутылка пива;
- кусок пиццы;
- бургер;
- шот с настойкой;
- картофель фри;
- крендель/закуска.

Все изображения должны быть вымышленными, без использования существующих торговых марок, логотипов и дизайна реальных алкогольных брендов.

В игре нет механики покупки или употребления алкоголя. Предметы используются исключительно как визуальные игровые элементы.

# 3. Лор

## 3.1. Место действия

Действие происходит в вымышленном городе **Неон-Сити**.

В старом квартале города находится гастробар:

**«Последний Заказ»**

Когда-то это было самое популярное место района, однако после появления огромного сетевого фуд-корта посетителей стало значительно меньше.

Главный герой устраивается в заведение перед его последним сезоном работы.

Задача игрока — помочь владельцу вернуть заведению былую популярность.

Каждая пройденная миссия означает ещё один успешно обслуженный вечер.

# 4. Персонажи

Для первой версии достаточно 3–4 сюжетных персонажей.

### Макс

Владелец заведения.

Добродушный, немного уставший человек, который постоянно говорит, что «раньше тут очередь стояла до соседнего квартала».

Выдаёт основные миссии.

### Рита

Бармен.

Объясняет специальные элементы, усилители и сложные комбинации.

### Чип

Курьер.

Используется в миссиях, связанных с доставками и предметами, которые необходимо опустить вниз игрового поля.

### Неон

Старый светящийся маскот заведения.

Может периодически «оживать» и давать подсказки.

Используется как юмористический элемент и визуальный символ игры.

---

# 5. Визуальный стиль

Основное направление:

**неоновый гастробар + современная мобильная казуальная игра.**

Не использовать реалистичную фотографическую стилистику.

Предметы должны быть:

- объёмными;
- яркими;
- легко различимыми;
- немного мультяшными;
- с мягкими бликами;
- с хорошо читаемым силуэтом.

Пример общего настроения:

неон + тёмно-синий фон + стекло + яркие вывески + тёплый свет еды.

Интерфейс не должен выглядеть как детская игра.

---

# 6. Основной игровой цикл

Основной цикл:

**Главное меню → выбор режима → игровая партия → получение результата → награда → прогресс → следующая партия.**

Во время партии:

1. Игрок меняет местами две соседние фишки.
2. Если образуется комбинация из 3 и более одинаковых элементов — они уничтожаются.
3. Игрок получает очки.
4. Верхние элементы падают вниз.
5. Пустые клетки заполняются новыми.
6. Если возникает новая комбинация без действий игрока — начинается каскад.
7. Каскады увеличивают множитель очков.
8. Комбинации из 4–5+ элементов создают специальные элементы.
9. После полного разрешения поля игрок может сделать следующий ход.

---

# 7. Игровое поле

Стандартное поле:

**8 × 8 клеток.**

Архитектура должна позволять создавать поля:

- 7 × 7;
- 8 × 8;
- 9 × 9;
- поля нестандартной формы;
- клетки, которые отсутствуют;
- заблокированные клетки.

Размер поля задаётся конфигурацией уровня и не должен быть жёстко прописан в коде.

---

# 8. Генерация игрового поля

При генерации новой партии обязательно:

1. На стартовом поле не должно быть автоматически готовых комбинаций 3+.
2. На поле должен существовать минимум один допустимый ход.
3. Если допустимых ходов нет, происходит автоматическое перемешивание.
4. После перемешивания поле снова должно содержать хотя бы один возможный ход.
5. Перемешивание не должно создавать неконтролируемые стартовые совпадения.

Для рейтинговых режимов генератор должен поддерживать **seeded RNG**.

Одинаковый seed + одинаковая последовательность действий должны всегда приводить к одинаковому результату.

Оба способа должны работать одновременно.

Во время взаимодействия с игровым полем страница не должна прокручиваться.

## ПК

Поддерживать:

- click → click;
- drag;
- мышь;
- trackpad.

Наведение мыши может слегка подсвечивать выбранную фишку.

# 10. Обычные игровые элементы

На стандартном поле одновременно используются шесть базовых типов.

### 1. Пиво

Стилизованная янтарная бутылка.

### 2. Пицца

Треугольный кусок пиццы.

### 3. Бургер

Яркий бургер.

### 4. Настойка

Небольшой шот с яркой жидкостью.

### 5. Картофель фри

Коробочка картофеля.

### 6. Крендель

Большой солёный крендель.

Типы должны различаться не только цветом, но и формой.

Это важно для пользователей с нарушением цветового восприятия.

---

# 11. Специальные элементы

## 11.1. Ракета

Создаётся при комбинации:

**4 одинаковые фишки подряд.**

Варианты:

- горизонтальная;
- вертикальная.

После активации уничтожает соответственно:

- всю строку;
- весь столбец.

Анимация:

быстрый запуск ракеты с неоновым следом.

---

# 12. Бомба

Создаётся комбинацией вида:

- T;
- L.

При активации взрывает большую область вокруг себя.

Рекомендуемый радиус:

**2 клетки.**

Эффект должен включать:

- небольшую задержку;
- вспышку;
- расширяющуюся ударную волну;
- частицы;
- короткий screen shake.

Screen shake должен отключаться настройкой «Уменьшение движения».

---

# 13. Молния

Создаётся комбинацией:

**5 одинаковых элементов в прямую линию.**

Представляет собой мощный специальный элемент.

При соединении молнии с обычной фишкой уничтожаются все фишки данного типа на игровом поле.

Пример:

Молния + Пицца → уничтожить всю пиццу.

Визуально между уничтожаемыми элементами проходят электрические разряды.

---

# 14. Комбинации специальных элементов

Специальные элементы должны взаимодействовать друг с другом.

### Ракета + Ракета

Создаёт крестовой удар по строкам и столбцам.

### Ракета + Бомба

Очищает несколько соседних строк и столбцов.

Ориентир:

3 строки + 3 столбца.

### Бомба + Бомба

Создаёт огромный взрыв увеличенного радиуса.

### Молния + обычная фишка

Удаляет с поля все фишки соответствующего типа.

### Молния + Ракета

Фишки выбранного типа превращаются в ракеты и последовательно активируются.

### Молния + Бомба

Фишки выбранного типа превращаются в бомбы и активируются.

### Молния + Молния

Очищает практически всё игровое поле.

Такие события должны сопровождаться особенно заметной анимацией и звуком.

# 15. Способности / бустеры

Кроме специальных фишек на поле игрок имеет расходуемые способности.

---

## Перекрашивание

Игрок:

1. выбирает способность;
2. выбирает фишку;
3. выбирает новый тип.

После изменения цвета/типа автоматически разрешаются возникшие комбинации.

Рабочее название:

**«Шейкер»**.

---

## Открывашка

Удаляет одну выбранную фишку или наносит один удар по препятствию.

---

## Перемешивание

Полностью перемешивает текущие обычные элементы поля.

Спецэлементы по умолчанию сохраняются.

---

## Стартовая ракета

Перед началом миссии на поле случайным образом появляется ракета.

---

## Стартовая бомба

Перед началом миссии появляется бомба.

---

## Стартовая молния

Редкий мощный бустер.

# 16. Режимы игры

Игра должна содержать минимум три основных режима.

---

# 17. Режим «Бесконечный»

Режим предназначен для спокойной игры без давления.

Особенности:

- отсутствует лимит ходов;
- нет проигрыша;
- поле существует бесконечно;
- очки постоянно накапливаются;
- состояние партии автоматически сохраняется;
- пользователь может закрыть игру и продолжить позже.

Игрок должен иметь кнопки:

**Продолжить**

и

**Новая игра**.

Перед созданием новой бесконечной игры необходимо предупреждать об удалении текущей партии.

Хранить:

- текущий score;
- максимальный score;
- количество ходов;
- максимальный каскад;
- созданные специальные элементы;
- seed;
- текущее состояние board.

---

# 18. Рейтинговый забег

Чтобы глобальный рейтинг не зависел от того, кто просто дольше играл в бесконечном режиме, создать дополнительный вариант:

**«Рейтинговый забег»**.

Например:

**50 ходов.**

Все игроки на протяжении одного дня получают:

- одинаковый seed;
- одинаковые правила;
- одинаковое стартовое поле;
- одинаковое количество ходов.

Бустеры из инвентаря запрещены.

Цель:

набрать максимальное количество очков.

Именно этот режим является основной основой глобального рейтинга.

---

# 19. Режим «Миссии»

Это основной сюжетный режим.

Структура:

**Глава → уровень → результат → звёзды → следующая миссия.**

Для версии 1.0:

**30 уровней.**

Три главы по 10 уровней.

В дальнейшем уровни добавляются через конфигурационные JSON-файлы без изменения движка.

---

# 20. Типы целей миссий

Поддержать следующие цели:

### Набрать очки

Например:

20 000 очков за 25 ходов.

### Собрать предметы

Например:

- 30 пицц;
- 25 бургеров.

### Уничтожить препятствия

Например:

разбить 20 кубиков льда.

### Опустить предмет

На поле появляется:

- чек;
- пакет доставки;
- ключ;
- заказ.

Необходимо довести его до нижнего края поля.

### Комбинированная миссия

Например:

- собрать 20 пицц;
- уничтожить 12 коробок;
- уложиться в 30 ходов.

---

# 21. Система звёзд

За миссию выдаётся:

### 1 звезда

Миссия выполнена.

### 2 звезды

Миссия выполнена и достигнут второй порог очков.

### 3 звезды

Достигнут максимальный порог.

Лучший результат сохраняется.

Количество звёзд используется для открытия следующих глав.

---

# 22. Препятствия

## Лёд

Находится поверх фишки.

После совпадения фишки получает удар.

Возможны:

- однослойный лёд;
- двухслойный лёд.

---

## Коробка

Занимает клетку и не перемещается.

Разбивается совпадением рядом или взрывом.

---

## Соус

Покрывает клетку.

Для очистки необходимо сделать рядом комбинацию.

---

## Закрытый поднос

Может иметь несколько уровней прочности.

---

## Цепь

Блокирует находящуюся в клетке фишку.

После разрушения цепи элемент снова становится обычным.

---

# 23. Режим «Головоломки»

Отдельный режим с заранее созданными задачами.

В отличие от миссий, здесь игрок должен найти конкретное решение.

Особенности:

- фиксированное стартовое поле;
- ограниченное число ходов;
- отсутствие обычных игровых бустеров;
- детерминированное поведение;
- возможность перезапустить задачу.

Для версии 1.0:

**20 головоломок.**

Минимум для MVP:

**8 головоломок.**

---

# 24. Подсказки

Если игрок ничего не делает приблизительно 8–12 секунд:

одна допустимая комбинация слегка подсвечивается.

Подсказка:

- не должна выполнять ход самостоятельно;
- не должна гарантировать лучший ход;
- просто показывает один допустимый вариант.

Настройкой подсказки можно отключить.

---

# 25. Каскады

Если после падения элементов автоматически образуется новое совпадение, увеличивается Combo.

Пример:

- Cascade 1 — ×1.00;
- Cascade 2 — ×1.25;
- Cascade 3 — ×1.50;
- Cascade 4 — ×1.75;
- далее рост до максимального ×3.

Значения должны храниться в конфигурации.

Не прописывать баланс жёстко в игровом коде.

---

# 26. Система очков

Начальная формула:

**100 очков за одну уничтоженную обычную фишку.**

То есть базовое совпадение трёх:

**300 очков.**

Дополнительно начислять бонус за:

- каскады;
- уничтожение препятствий;
- создание спецэлементов;
- активацию спецэлементов;
- комбинации спецэлементов.

Все коэффициенты должны находиться в отдельном конфигурационном файле.

Например:

`game-balance.json`

Это позволит менять баланс без переписывания механики.

# 28. Внутренняя валюта

Рабочее название:

**Крышки.**

Получаются:

- за прохождение миссий;
- за получение звёзд;
- за достижения;
- из ежедневной награды;
- за некоторые головоломки.

На первом этапе реальные платежи отсутствуют.

Крышки используются для получения игровых бустеров и косметических элементов.

# 29. «Плюшки»

Чтобы у игры появилась дополнительная мотивация, реализовать:

### Ежедневный подарок

Игрок получает небольшой подарок за первый запуск дня.

### Серия дней

Можно добавить серию до 7 дней.

Не делать её критичной для игрового процесса.

### Достижения

Примеры:

- создать 100 ракет;
- выполнить каскад ×5;
- получить 30 звёзд;
- пройти 10 головоломок;
- уничтожить 1000 бургеров;
- набрать 1 000 000 суммарных очков.

### Косметика

В дальнейшем можно открывать:

- альтернативное игровое поле;
- другие неоновые рамки;
- эффекты взрывов;
- фон гастробара;
- оформление фишек.

# 31. Экран игрового процесса

Верхний HUD:

- кнопка паузы;
- номер миссии/режим;
- текущий score;
- количество оставшихся ходов;
- цель уровня.

Основная часть:

**игровое поле.**

# 36. Правила рейтинга

Нельзя считать обычный score, присланный JavaScript-клиентом, достоверным.

Пользователь может открыть DevTools и самостоятельно отправить произвольное число.

Поэтому рейтинговый режим должен работать через проверяемые игровые сессии.

Backend создаёт:

- `sessionId`;
- `seed`;
- конфигурацию;
- дату окончания;
- количество ходов.

Клиент записывает последовательность действий игрока.

Например:

`A3 -> A4`

или координаты:

`{from:[2,3], to:[2,4]}`

После завершения клиент отправляет:

- `sessionId`;
- список ходов;
- итоговый score.

Backend повторно проигрывает партию через ту же детерминированную игровую логику.

Если серверный результат совпадает с клиентским:

`verified = true`

и score попадает в рейтинг.

Если нет:

результат отклоняется.

# 50. Telegram-авторизация

Нельзя доверять данным:

для идентификации игрока.

`Telegram.WebApp.initData`

на backend.

Backend выполняет проверку подписи Telegram.

Только после успешной проверки Telegram ID считается достоверным.

Telegram прямо требует проверять `initData` на backend и предупреждает не доверять `initDataUnsafe`.

Нельзя сохранять board посередине падения фишек.

**быстро;**

**сочно;**

**понятно;**

**приятные каскады;**

**мощные спецэффекты;**

**короткие загрузки;**

**приятный звук;**

**узнаваемый неоновый стиль;**

Именно такие моменты должны создавать желание сыграть «ещё одну партию».
# Дополнение реализации — MVP-2, 2026-09-10

Исходные разделы 1–86 выше сохранены. Ниже зафиксированы уточнения неоднозначных правил второго этапа и границы стенда.

- Четыре по горизонтали создают горизонтальную ракету, по вертикали — вертикальную.
- На связанную группу совпадений создаётся максимум один special; приоритет: линия 5+ → T/L → линия 4. Независимые группы создают specials независимо.
- Точка создания — обычная фишка в группе: приоритет клетки назначения ручного swap, затем исходной клетки, пересечения и наименьшего индекса. В каскадах используется пересечение/наименьший индекс. Старый special не перезаписывается.
- Новый special не удаляется/не активируется в той же волне, где создан. Далее подчиняется gravity и обычным правилам активации.
- Ракеты и бомбы сохраняют базовый тип и участвуют в matches. Молния не образует обычные matches. При попадании взрывом молния очищает свой сохранённый тип.
- Бомба очищает квадрат радиусом 2 (до 5×5). Двойная бомба — квадрат радиусом 4 (до 9×9). Обрезка по границе поля.
- Центр пары specials — клетка назначения swap. Ракета+ракета — одна строка и один столбец; ракета+бомба — три строки и три столбца.
- Молния+special использует тип партнёра; остальные фишки этого типа превращаются в specials и активируются. Для ракет H/V чередуются детерминированно по индексу. Партнёр пары тоже срабатывает один раз. Молния+молния очищает всё поле.
- Любой special активируется максимум один раз за волну. Очистка одного индекса не начисляет очки повторно.
- За каждую фактически удалённую фишку начисляется 100 × cascade multiplier. Якорь создания не считается удалением. Бонусы вне множителя: создание +200, активация +100, пара +500; все параметры находятся в balance.ts.
- Shuffle сохраняет specials на своих местах и переставляет только обычные фишки.
- Локальные сохранения v1 мигрируют в v2 без сброса board/RNG/score. Дальнейшая игра использует mvp2-v1; старые ranked replays требуют старую версию правил.
- Для проверки анимаций и звука MVP-2 добавлен локальный Canvas 2D/Web Audio стенд с временными символами и синтезированными SFX. Phaser/Vite из рекомендованного стека остаются задачей полноценного клиента MVP-3. Этот стенд не является реализацией всех экранов MVP-3 или финальных assets MVP-10.
