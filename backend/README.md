# Онлайн-рейтинг NightShift

Код сервера подготовлен, но **внешняя база, Telegram-бот и хостинг API не подключены и не проверены вживую**. Статическую игру можно разместить на GitHub Pages без этих компонентов; рейтинговая тренировка доступна автономно.

## Развёртывание

1. Создайте отдельный проект Supabase и выполните `backend/schema.sql` в SQL Editor. Скрипт создаёт `profiles`, `challenges`, `ranked_sessions`, `rate_limits`, индексы и RPC. Перед применением к существующему проекту проверьте имена таблиц; файл рассчитан на отдельную базу игры. Не запускайте его вслепую поверх чужой схемы.
2. Создайте Telegram-бота через BotFather и назначьте Mini App URL опубликованной игры по HTTPS.
3. На **сервере**, скопируйте `backend/.env.example` в `backend/.env` и задайте значения. Секреты не должны попадать в `public`, `dist`, GitHub Pages или git. `AUTH_SECRET` — случайная строка минимум 32 символа. `ALLOWED_ORIGIN` — origin, например `https://name.github.io`, без пути репозитория.
4. На машине с Node.js 22+: `node --env-file=backend/.env backend/server.mjs`. Готовое `dist/game/core` и `dist/config` входят в архив. При изменении core сначала пересоберите проект.
5. Разместите API на отдельном HTTPS-хостинге Node.js или в контейнере. Для контейнера используйте Dockerfile и передавайте переменные окружения при запуске. GitHub Pages не исполняет этот сервер. При работе за reverse proxy ограничьте запросы также на прокси: встроенное IP-ограничение видит адрес непосредственного соединения и намеренно не доверяет произвольному X-Forwarded-For.
6. В `public/runtime-config.json` укажите публичный HTTPS URL API в `apiBase`, затем пересоберите и опубликуйте `dist`. В этом файле нужен только URL — никаких ключей. Если публикуете готовый dist без сборки, изменение конфигурации нужно повторить в `dist/runtime-config.json`.
7. Пройдите контрольный сценарий в Telegram: вход → `/auth` → старт → 50 ходов → отправка → запись verified → рейтинг. Проверьте неверную подпись, изменённый score, повторную отправку и истёкшую сессию.

## API

- `GET /health` — доступность и версия правил.
- `POST /auth` — `{initData}`; проверка HMAC и возраста до часа, возврат короткоживущего bearer token.
- `POST /session` — авторизованный старт; общий seed дня, sessionId, срок и 50 ходов. Первый старт дня атомарно фиксирует seed в БД.
- `POST /submit` — `{sessionId,moves,score}`. Seed, правила, владелец и срок берутся из БД. Сервер повторяет 50 ходов и сравнивает счёт. Финализация блокирует строку, чтобы избежать двойной записи; повтор идентичного принятого payload возвращает тот же результат.
- `GET /leaderboard?period=day|week|season` — TOP-100 и соседи авторизованного игрока. Неделя — с понедельника UTC, сезон — текущий календарный месяц. Для длинных периодов суммируется лучший результат каждого дня.

RLS включён на всех таблицах. `anon` и `authenticated` не имеют прямых прав на данные и серверные RPC. Только серверный service-role вызывает функции. Это собственная Telegram-авторизация API; Supabase Auth в этой версии не используется.

Встроенные ограничения — 120 запросов/IP/минуту, 30 запросов/пользователя/минуту, 10 авторизаций и 3 старта в минуту. Ограничители атомарны в PostgreSQL. Для продакшена настройте очистку старых записей rate_limits и политику хранения логов/ходов по требованиям владельца.

## Проверенные части и границы

Автоматически проверены HMAC, срок initData, подмена данных, токены, срок токенов и детерминированный replay. SQL/RLS/RPC и HTTP→Supabase интеграция не исполнялись на реальной БД. Эти части требуют проверки после подключения проекта; их готовность к продакшену не заявляется.

Официальные справочники, использованные при реализации:
- Telegram Mini Apps: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
- Supabase server authentication: https://supabase.com/docs/guides/functions/auth
